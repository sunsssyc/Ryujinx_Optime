# 修复说明（Ryujinx_Optime · 原生 Metal 后端）

本分支相对上游修复过的画面、稳定性和性能问题，按时间倒序。每项都写了看到的现象、真正的原因、修复提交，以及能复现旧问题的开关（方便对照）。英文的详细台账见 [METAL_BUG_LEDGER.md](METAL_BUG_LEDGER.md)，更长的排查过程在 `docs/` 下的各份 hand-off 文档和提交信息里。

使用方法与开关说明见 [本地使用指南](METAL_FORK_GUIDE.md)。

## 画面与稳定性

### 空岛天上单帧出现倾斜大平面或竖长条（2026-09-15）

- **现象**：在初始空岛（Great Sky Island）跑图时，天上偶尔闪出一块倾斜的大平面或一条竖长条，只持续一帧。Vulkan 后端同样有。
- **原因**：客户机提交一批 GPU 命令后，约 11–21 毫秒就开始往常量缓冲里写下一帧的数据；而模拟器的 GPU 线程要到提交后 36–44 毫秒才执行到这批命令里的绘制。某个常量槽如果下一帧换成了另一个物体，这一帧的网格就会用那个物体的变换画出来。相关代码与上游一致，推断官方版本也有同样的竞争。
- **修复**：`ba7b7ed0`（v522）
  - 提交线程在返回客户机之前，解析这批命令里的常量缓冲绑定，把绑定范围的内容拷贝下来。这批命令的绘制绑定这些副本（每批只上传一次），不再读已被改写的内存。
  - 批次里的内联常量更新、执行时的 GPU 写入、物理地址变动，都会让受影响的副本失效，回到原来的路径。
  - 满 1024 个条目的大批次按每段至少 512 个条目切成 2–4 段，由提交线程和 3 个辅助线程并行解析、拷贝，全部完成才返回，保护不减。
- **验证**：
  - 带探针的版本逐帧检测：修复开时 0 个故障帧，关时 83 个。用户走图目视不再闪（v513、v516），并行版试玩也不闪（v521、v522）。
  - 并行版在真实抓取的命令流上与串行版逐个比较关联结果，差异为 0。
  - 代价（重场景、同一进程内热切换对比）：串行版帧率 −8.1%，并行版 −4.0%。碰到 50 帧上限的轻场景看不出代价。
- **开关**：`RYUJINX_UBO_SUBMIT_SNAPSHOT=0` 关闭修复；运行中 `/tmp/ryujinx-ubo-snapshot` 写 0 关闭、1 开启。`RYUJINX_UBO_OPT=0`，或运行中 `/tmp/ryujinx-ubo-opt` 写 0，改回由提交线程串行解析。

### 停止模拟后回不到游戏列表（2026-09-11）

- **现象**：停止模拟后主窗口停在黑屏，日志里出现 `off-thread buffer dispose` 和 `cross-thread flush marshalled` 警告，进程要强制退出。
- **原因**：多线程渲染器先停掉命令循环，再在调用线程（界面线程）上销毁 Metal 渲染器，而原来跑循环的渲染线程被主程序留着做收尾。销毁时最后一次刷新按"跨线程"处理，被提交给那个已经不再处理命令的循环去等，永远等不到。
- **修复**：`2f8399d6` + `502793e6`，销毁时由调用线程接管命令缓冲池，循环停止后的中断请求就地执行。
- **验证**：停止后 0 条警告，主窗口正常回到列表。

### 转视角顿挫：管线状态同步构建（2026-09-12）

- **现象**：转向没见过的材质时一顿，偶尔卡住近一秒。
- **原因**：每种材质与渲染状态的组合都要向驱动申请一个管线状态，原来在渲染线程同步等它建好。系统缓存命中时单个只要 0.3 毫秒，但转视角时一帧里会来一两百个；缓存未命中的冷构建要几十毫秒到一秒多。
- **修复**：`02376448`（v491），构建交给线程池并行做，绘制遇到还没建好的管线先等，每帧总共最多等 4 毫秒，超出才跳过该绘制（下一帧补上）。顺带修了 `PipelineUid` 的对象比较无限递归。
- **验证**：同存档同点位各转几圈，2K：超过 40 毫秒的帧 129 → 38，超过 60 毫秒的 54 → 6，最长一帧 1751 → 197 毫秒，中位帧时不变。
- **开关**：`RYUJINX_METAL_ASYNC_PSO=0` 回到同步；`RYUJINX_METAL_ASYNC_PSO_WAIT_MS` 调等待预算。
- **补充（v492）**：全屏绘制（3–6 顶点的后处理、曝光、色调映射）和一帧内排队超过 64 个之后的绘制不再跳过，改为原地构建或不限时等待，避免跳过全屏绘制造成整帧发白；稳定游玩时跳过归零，只在读档爆发帧出现。


### 雪山石台单帧消失（2026-09-06 / 09-11）

- **现象**：在赫布拉雪山的石台上站着不动，大约每秒一次，脚下的石板平台被后面的雪地和岩石顶替一帧，下一帧恢复。
- **原因**：游戏在两段绘制之间会发"纹理屏障"，要求前面画的东西对后面可见。Metal 上兑现屏障意味着结束渲染通道、把图从片上缓存存回显存，很贵。旧策略（`hazard`）在屏障那一刻看当前绑定的贴图来决定能否跳过，但那套绑定属于上一条绘制，真正要读新图的绘制还没绑上来。跳过后，平台那条绘制在同一个通道里读到了还没存回显存的旧深度，整条被判为遮挡，一个像素也没画。
- **修复**：
  - `5b5e7519` 先把默认值改回 `all`，每个屏障都老实结束通道。
  - `6544bd16` 新增 `deferred` 模式：屏障不再立即结束通道，而是给本通道已写的附件打标；后面哪条绘制真的读到带标的附件，就在那条绘制之前拆通道。没人读的屏障一个通道也不花。
  - `066df9ab` 把 `deferred` 设为默认。
- **验证**：同一位置、同一进程内热切换，`hazard` 复现、`deferred` 不复现。该位置每帧 34 个屏障被延迟，只有 0.4 次真正需要拆，通道数与旧策略持平（262 对 266），省下的性能保住了。
- **开关**：`RYUJINX_METAL_BARRIER_SCOPE=all` 回到最保守档；`=hazard` 复现旧问题。

### 游戏自身中止时不留原因（2026-09-06，诊断）

- **现象**：游玩中闪退，日志只有一句 `The guest program broke execution!`。
- **情况**：这类闪退是游戏自己断言失败后主动中止，不是渲染崩溃。那一次发生在游戏线程等待条件变量时，最可能的原因是持锁线程退出。模拟器原本丢掉了游戏传出的错误码，也不记录这类"预期内"的失败结果，所以无法判断是模拟器内核的问题还是游戏或 Mod 的时序问题。
- **改动**：`0bd64783` 在三处补日志：条件变量等待失败、线程退出时释放了哪些等待者、svcBreak 带出的错误码。只在失败路径触发，不影响正常运行。下次再遇到就能定位，搜索方法见使用指南。

### 墙面和地面阳光单帧跳变（2026-09-05）

- **现象**：在神庙手动存档处站着，墙面、地面的阳光亮度偶尔跳一帧。
- **原因**：准备绘制资源时可能会中途换掉渲染编码器，而"脏状态"检查在换之前已经做完，新编码器上有些资源绑定没有重新设置。
- **修复**：`2fe2cec8`，编码器切换后重新准备全部渲染绑定；同一提交还修正了从缓存加载着色器时漏传输出通道表的问题。
- **验证**：6000 帧内跳变从 16 次降到 0 次；600 秒游玩加录屏复核无跳变。
- **开关**：`RYUJINX_METAL_PREPASS_REBIND=2` 只记录不修复。

### 山坡存档处黑色贴花块（2026-09-03 / 09-04）

- **现象**：黑色多边形随绘制顺序闪烁，还有黑色楔形。
- **原因**：一条绘制读的正是自己在写的颜色槽，用片上读取（framebuffer fetch）时背面读到了正面刚写的新值；另外旧屏障策略跳过了保护"片元写存储缓冲"的屏障。
- **修复**：`e186fff2`（自己写的槽不走片上读取）、`c0f67455`（这两类屏障一律保留）。
- **验证**：连拍差分的变化格从 301 降到 0，另一处从 241/291 降到噪声水平。

### 水面变成平铺的沙石贴图（2026-09-03）

- **原因**：水面折射会在偏移位置采样场景图，而片上读取只能读当前像素，读出来的是自己。
- **修复**：`02f6962c`，片上读取只用于 R32F 深度这类必定同像素的读。

### 五种编码器生命周期崩溃（2026-08-30）

- **现象**：重复提交、重复结束编码器、提交时编码器仍在工作等多种崩溃。
- **原因**：非渲染线程（同步、计数器、暂存区、纹理回读）直接调用了刷新命令的函数，和渲染线程抢同一个编码器。
- **修复**：`46b58c0c`，跨线程的刷新一律封送回渲染线程执行。

### 地底地图层消失一帧（2026-08-29）

- **现象**：地底地图的地形、网格和边框消失一帧，界面其余部分正常。官方原版同样有这个问题。
- **原因**：纹理池取缓存的纹理时不核对描述符。某个槽位在每帧同步之后被改写，拿到的还是上一个占用者。
- **修复**：`7c1d8ef4`。**验证**：10 分钟内 10 次降到 0 次。**开关**：`RYUJINX_POOL_DESC_CHECK=0` 复现。

### 整体画面偏暗（2026-08-26）

- **现象**：画面整体偏暗，地底尤其明显，最多暗 6.5 倍。
- **原因**：输出画面时把普通纹理换成了它的 sRGB 版本（早期白闪缓解措施的遗留），多解码了一次伽马。
- **修复**：`3d33ab70`。亮度分位数与官方 1.2 版逐位一致。**开关**：`RYUJINX_GPU_PRESENT_SIBLING=1` 复现。

### 地底雾变成青色硬边石板（2026-08-26）

- **原因**：着色器转换成 MSL 时丢掉了 `texelFetch` 的常量偏移，12 次邻域采样全落在同一个像素。
- **修复**：随 CodeGenVersion 7378 修复，对照开关在 `b1a39608`。**开关**：`RYUJINX_MSL_FETCH_OFFSET=0` 复现。

### 白天全屏白闪（偶尔发红）（2026-08-26）

- **原因**：着色器翻译器删除死代码时连锁清空了一个仍然有用的函数调用的参数，太阳可见度计算读到未初始化的值，1×1 的自动曝光纹理这一帧饱和成纯白。
- **修复**：`01a1e37f`，机制定位在 `e63dc628`。早先的画面层缓解（FlashGuard）已撤回。

### 地底草丛整片消失（2026-07-25）

- **原因**：剔除模式在"未启用剔除"时仍按寄存器里的旧值设成"正反面都剔除"，后端用 0×0 剪裁矩形模拟这种情况，双面植被卡片一个像素都画不出来。
- **修复**：`ab451955`。

### 瘴气在安全位置也造成伤害（2026-07-25）

- **现象**：地底边缘一些在 Vulkan 上安全的位置，走过去会掉血。
- **原因**：后端向核心谎报"顶点着色器不支持写存储缓冲"，于是带存储写的顶点着色器改走计算着色器模拟路径，写入没有落到缓冲里。游戏判定瘴气伤害时回读这块数据，读到全零，按"有瘴气"处理。
- **修复**：`45cc9d87`，如实声明支持。此后没有再出现。

### 瘴气变成稀疏红色条纹（2026-07-24）

- **原因**：Metal 的 3D 纹理不支持块压缩格式，后端却声明支持，4 张 BC4 体积噪声纹理解码成了乱码。
- **修复**：`14c8533e`。

### 近处植被闪烁或消失（2026-07-19）

- **原因**：非索引绘制走拓扑转换路径时丢了实例数、起始顶点和起始实例。
- **修复**：`b2f08b2e`。

### Metal 验证层报出的五类未定义行为（2026-07-19）

- 纹理用途未声明、计算管线虚报 SIMD 宽度、计算屏障作用域非法、mip 拷贝越界、剪裁矩形超出通道尺寸。
- **修复**：`161aa69c`、`9ddf5f2f`、`93c44024`。开启 Metal 验证层后报错数归零。

### 画面偏青、暗部死黑（2026-07-18）

- **原因**：`CAMetalLayer` 没有设置色彩空间，sRGB 图像在 P3 屏幕上被原样显示。
- **修复**：`bd4827f1`。

## 性能

Metal 后端在这款游戏上是 GPU 瓶颈，帧时间主要由每帧渲染通道数决定（每个通道都要把附件存回显存再读回）。以下几项是减少通道数的主要改动：

| 提交 | 改动 | 效果 |
|---|---|---|
| `e5d8c073`、`1417564a` | 按 Switch 原生语义，放行没有屏障保护的自读，不再为此拆通道；后者限定到安全的格式并转为默认 | 实测场景 27.8 → 44.7 fps，每帧通道 530 → 198 |
| `d5835430` | R32F 深度的同像素自读改用片上读取 | 省掉软粒子、深度淡出一类的拆分 |
| `066df9ab` | 延迟兑现游戏纹理屏障（见上文雪山石台） | 与旧策略同样省通道，同时修掉单帧消失 |
